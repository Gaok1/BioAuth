## Ressalvas

**1. Desvio do contrato do plano — leia antes de integrar.**

`docs/parallel-work-plan.md` especificou o comando `vault.copy` com `item_id` e `revision`. Esse comando **não foi implementado**, porque não existe store do cofre deste lado: `VLT-02` é o store no telefone e o handler que buscaria o segredo é `VLT-04`/`T6`. Implementá-lo agora produziria um método que só sabe retornar "não implementado".

No lugar entrou **`vault.generate-copy`**, que é completo hoje: gera pelo `password::generate` que já existe, escreve em páginas travadas e copia. Mesmo caminho de clipboard que um segredo buscado vai usar.

```
vault.generate-copy
  params: { length?, lowercase?, uppercase?, digits?, symbols?, clearAfterMs? }
  result: { length, clearsAtMs, historyExcluded, cloudExcluded, memoryLocked }
```

Todo campo de params é opcional e cai no default do gerador, então `{}` é uma chamada válida. `T6` deve acrescentar `vault.copy` chamando `clipboard::copy_secret` com o segredo que vier do telefone — a assinatura pública que ele precisa é `copy_secret(&SecretBuffer, Duration) -> Result<CopyOutcome, ClipboardError>`.

**2. O caminho Linux não foi executado.** Compila e passa clippy para `x86_64-unknown-linux-gnu`, verificado isolando os dois módulos num crate de rascunho para não arrastar o `bluer`. Mas `mlock`, `madvise`, `wl-copy` e `xclip` nunca rodaram. A seleção Wayland-antes-de-X11 é função pura e tem teste; o `spawn` em si não tem. **Não marque `✅` sem uma máquina Linux.**

**3. Os testes mexem no clipboard de verdade.** Rodar a suíte apaga o que o desenvolvedor tinha copiado. Não achei como evitar sem deixar de testar a coisa que importa. Eles serializam por `clipboard::test_lock()` — descoberto quando o teste de IPC novo passou a corridar com o de expiração; o clipboard é um recurso por sessão e dois testes paralelos se sobrescrevem.

**4. A suíte ficou ~11s mais lenta.** `MIN_TTL` é 5s e dois testes esperam a expiração real, agora em série. Encurtar `MIN_TTL` só para o teste tornaria o teste mais rápido e o produto pior.

**5. O que a memória travada não cobre**, já registrado em `docs/dependencies.md` e repetido aqui para quem ler só isto: hibernação escreve a RAM inteira em disco e ignora o lock; e enquanto a entrada está viva o próprio SO mantém uma cópia em claro do texto do clipboard, em memória que este processo não possui. `secret_memory` protege a nossa cópia, não a dele.

**6. Falha do `WerRegisterExcludedMemoryBlock` é silenciosa.** É best-effort — a API é do Windows 10 1709 em diante e retorna `HRESULT` de falha em builds mais antigos. Não afeta `is_locked()`, que reporta só o `VirtualLock`, e não aparece no resultado do IPC. Se a exclusão de dump virar uma garantia mostrada ao usuário, isso precisa de um campo próprio.

**7. Documentação de método pendente para o integrador.** `vault.generate-copy` deveria estar em `docs/desktop.md`, junto dos outros métodos de IPC. Não editei: a regra de propriedade do plano me dá só este arquivo, e `desktop.md` não é meu. Os módulos estão documentados por dentro.

## Verificação que vale repetir

O teste `ipc::concurrent_client_tests::a_generated_password_reaches_the_clipboard_but_not_the_caller` é o que sustenta a regra "plaintext nunca entra no Electron". Ele não confere o formato do struct — vai pelo socket real, lê o que de fato caiu no clipboard, e procura esse texto nos bytes crus da resposta. Um campo novo, um eco de debug ou uma mensagem de erro carregando a senha falham ali.

O teste `clipboard::tests::expiry_leaves_a_later_copy_alone` foi verificado como não-vazio: trocando `if sequence() == ours` por `if true`, ele falha com `left: None`. Sem essa checagem o timer apagaria o que o usuário copiou depois — perda de dado vestida de recurso de segurança.
